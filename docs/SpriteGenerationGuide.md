# Grave of the Fallen — AI 스프라이트 제작 명세

검토 기준: 2026-10-24의 게임 코드. 이 문서는 **이미지 제작·납품 규격**이며, 게임 로직 변경 요청이 아니다.

이 문서는 현재 구현된 게임에 적용할 픽셀 아트 스프라이트를 이미지 생성 AI에 요청하기 위한 독립형 제작 브리프다. AI는 이 문서에 없는 캐릭터·장비·기능을 임의로 추가하지 말고, 한 번에 모든 자산을 한 장에 만들지 말고 아래 제작 순서에 따라 자산 하나 또는 같은 계열 한 묶음씩 생성한다.

> 게임 규칙의 원본은 [플레이어](Player/AGENTS.md), [직업](Classes/AGENTS.md), [적](Enemy/AGENTS.md), [전투](Combat/AGENTS.md), [성장](Progression/AGENTS.md), [UI](ui/AGENTS.md) 지침이다. 아래 판정 정보는 그림의 위치와 크기를 맞추기 위한 제작용 스냅샷이며 게임 규칙을 새로 정하지 않는다. 이미지 생성 AI는 저장소나 링크를 열지 않아도 본문만으로 제작할 수 있다. 규격을 통과한 파일의 납품과 게임 연동은 별도다. **세 직업·좀비·적 9종·투사체·경험치 구슬·전투 효과는 사용자 제공 이미지의 가공본을 실제 게임에 적용했다.** 현재 구현된 가공·레이어 예외는 13절을 따르며, 바닥·울타리·장애물 등 나머지 자산은 제작 목표다.

### 문서만 입력했을 때의 기본 실행

- 이미지 생성이 가능한 AI라면 추가 질문 없이 10.1절의 `warlock_idle_down_00.png` 한 장부터 실제로 생성한다. 이 문서를 요약하거나 전체 자산을 합친 포스터를 만드는 것으로 작업을 대신하지 않는다.
- 사용자가 ID·애니메이션·범위를 지정하면 그 요청을 우선한다. `P0 전체`를 요청받으면 10절 순서로 나누어 제작하고 완료·미완료 파일을 기록한다. 한 응답의 생성 한도를 넘으면 다음 시작 파일을 명시한다.
- 크기·알파·시트 정렬을 실제로 검사할 수 없는 도구는 결과를 `raw`로 표시한다. 검사한 최종 PNG만 `ready`로 표시한다. 이미지 생성이나 파일 저장 자체가 불가능하면 그 제한을 알리고 제작용 프롬프트를 제공하되, 파일을 만들었다고 쓰지 않는다.

## 1. 게임과 화면 구성

- 장르: Vampire Survivors 변형 스타일의 2D 탑다운 액션 로그라이크
- 분위기: 몰락한 묘지, 죽은 숲, 고딕 철제 울타리, 쇠락한 성역
- 대립 구도: 악역 계열 플레이어 3종과 좀비 대 성기사단·교단 계열 적
- 게임 내부 해상도: 1280×720
- 월드 크기: 3000×3000
- 시점: 완전한 정수리가 아니라 얼굴·가슴·무기와 발 위치가 함께 읽히는 **탑다운 3/4 시점**
- 카메라: 플레이어를 따라 이동하며 줌 변화는 없음
- 렌더링: `pixelArt: true`; 발밑 월드 Y 좌표를 기준으로 앞뒤 가림
- 현재 상태: 월드와 장애물은 코드 생성 픽셀 텍스처, 세 직업은 가공된 PNG 몸체·마법/검격 레이어, 좀비와 적 9종은 PNG 몸체, 투사체·경험치 구슬·전투 효과는 PNG 가로 시트(효과는 정확한 범위 도형 위에 겹침)

후반 일반 적 생성 상한은 90마리이며 보스는 이 상한의 예외다. 작은 크기에서도 진영, 병종, 위험도를 즉시 구분할 수 있어야 하며 장식보다 실루엣과 색 구분을 우선한다. 아래 픽셀 크기는 브라우저 창 크기가 아니라 **게임 내부 좌표 기준**이다. 창 맞춤 확대·축소는 파일 크기에 반영하지 않는다.

## 2. 절대 제작 규칙

### 2.1 화풍

- 오리지널 다크 고딕 판타지 픽셀 아트로 제작한다. 특정 게임, 작가, IP의 화풍이나 캐릭터를 복제하지 않는다.
- 큰 픽셀 덩어리, 1~2px 외곽선, 제한된 팔레트, 명확한 명암 3~5단계를 사용한다.
- 안티앨리어싱, 흐림, 사진 질감, 벡터처럼 매끈한 가장자리, 과도한 그라데이션을 사용하지 않는다.
- 광원은 화면 왼쪽 위에서 오는 차갑고 약한 달빛으로 통일한다. 금속의 가장 밝은 면도 순백색 면적으로 넓게 칠하지 않는다.
- 캐릭터의 발은 항상 같은 기준선에 고정한다. 이동·공격 중 몸이 상하로 흔들려도 발 기준점이 프레임마다 떠다니면 안 된다.
- 바닥과 합쳐진 그림자, 원형 후광, 배경, UI 프레임, 글자, 숫자, 워터마크를 넣지 않는다. 필요한 접지 그림자는 게임에서 별도로 처리한다.
- 마법 투사체와 이펙트를 제외한 스프라이트에 반투명 가장자리나 바깥 광채를 넣지 않는다.
- 무기와 망토가 프레임 경계에서 잘리지 않게 한다.
- 최종 해상도의 1px을 최소 단위로 그린다. 저해상도 그림을 흐리게 확대하거나, 자산마다 도트 크기·외곽선 두께를 다르게 만들지 않는다. 장애물의 기존 코드 텍스처는 2배로 표시되지만 아래 PNG는 이미 최종 표시 크기다.
- 타일·울타리 연결부를 제외하고 불투명 실루엣은 셀 경계에서 최소 2px 떨어뜨린다. 캐릭터의 접지 기준은 2.4절을 따른다.

### 2.2 파일과 투명도

- 결과물은 알파 채널이 있는 PNG로 납품한다.
- 캐릭터·투사체·구슬·이펙트·장식·장애물은 물체 밖을 완전 투명으로 만든다. 흰색·검은색 체크무늬나 단색 배경을 이미지에 합성하지 않는다. **예외: 바닥 타일은 전체 픽셀이 불투명(alpha=255)**이며 투명 구멍이 없어야 한다. 모서리 기둥의 석재 바닥은 물체 자체이므로 불투명하게 그려도 된다.
- 색상 모드는 sRGB, PNG truecolor RGBA, **채널당 8-bit(총 32-bit)**를 사용한다. 캐릭터·장애물·장식·울타리·구슬의 알파는 0 또는 255만 사용하고, 마법 투사체와 이펙트에만 의도한 반투명 픽셀을 허용한다. alpha=0인 픽셀의 RGB는 후처리 때 0으로 정리한다.
- JPEG, WebP, GIF는 사용하지 않는다.
- 스프라이트 시트에는 제목, 방향명, 프레임 번호, 구분선, 여백용 색상 블록을 넣지 않는다.
- AI가 정확한 시트 정렬을 보장하지 못하면 **개별 프레임 PNG를 우선 납품**하고, 정렬된 시트는 후처리 단계에서 만든다.
- 자동 트리밍, 셀별 리사이즈, 회전 패킹, 아틀라스 패킹을 하지 않는다. 투명 여백도 규격의 일부다. 개별 프레임을 합칠 때 확대·보간 없이 지정 좌표에 그대로 복사한다.
- 생성 도구가 작은 출력 크기를 지원하지 않으면 큰 원본은 `raw/`에 보관한다. 최종 축소는 최근접 보간으로 하고 도트·실루엣·기준점을 다시 교정한다. 축소만으로 정확한 픽셀 아트와 애니메이션 일관성이 보장된다고 간주하지 않는다. 알파 없이 생성된 배경은 실제 제거·검사 전까지 납품 규격 통과로 보지 않는다.

### 2.3 방향과 시트 배열

- 캐릭터와 생물은 4방향을 사용한다.
- `down`은 화면 아래를 향한 앞모습, `up`은 화면 위를 향한 뒷모습, `left/right`는 각각 화면 왼쪽/오른쪽을 향한 옆모습이다. 카메라 높이는 고정하고 방향만 바꾼다. 등각 투영의 대각선 방향이나 정수리만 보이는 시점으로 바꾸지 않는다.
- 시트의 행 순서는 반드시 `down`, `left`, `right`, `up`이다.
- 한 애니메이션마다 별도 시트를 만든다. 열은 시간 순서의 프레임이다.
- 프레임 사이 간격과 바깥 여백은 0px로 한다.
- 모든 프레임 셀의 크기와 발 기준점은 동일해야 한다.
- 네 방향에서 같은 인물·장비·체형·의상 손상을 유지한다. 좌우 반전은 초안에만 쓸 수 있고, 최종본에서는 해부학적 손 위치·문양·왼쪽 위 광원을 교정한다. 방패와 주무기의 손이 바뀌면 안 된다.

| 애니메이션 | 프레임 수 | 권장 재생 속도 | 용도 |
| --- | ---: | ---: | --- |
| `idle` | 4 | 6fps | 대기, 호흡, 천이나 불빛의 미세한 움직임 |
| `walk` | 6 | 10fps | 일반 이동. 첫 프레임과 마지막 프레임이 자연스럽게 연결되어야 함 |
| `attack` 또는 `cast` | 6 | 12fps | 근접 공격, 발사, 회복, 주문 시전 |
| `hurt` | 2 | 12fps | 선택 사항. 현재 게임은 점멸로도 피격을 표시할 수 있음 |
| `death` | 8 | 10fps | 선택 사항. 비반복. 마지막 프레임은 시각 연출에만 사용 |

현재 게임에 먼저 적용할 최소 세트는 `idle`, `walk`, `attack/cast`다. `hurt`와 `death`는 2차 제작 대상으로 삼는다.

- `idle/walk`만 반복한다. `walk`의 6장은 서로 다른 보행 위상이며 마지막 칸에 첫 칸을 복제해 멈칫거림을 만들지 않는다.
- `attack/cast`의 0-based 열은 `0 준비 → 1 힘 모으기 → 2 타격·발사·회복의 시각적 정점 → 3 후속 동작 → 4 복귀 → 5 기본 자세`다. 마지막 자세는 같은 방향 `idle` 첫 장으로 이어진다.
- 발 기준점은 움직이지 않지만 보행 중 한쪽 발을 드는 것은 허용한다. 공격에 캐릭터 전체가 셀 안을 전진하는 루트 이동을 넣지 않는다. 실제 위치 이동은 게임이 담당한다.
- 위 fps는 제작 미리보기 값이다. 이동 중 자동 공격과 성장으로 빨라지는 공격을 유지해야 하므로 애니메이션 종료를 기다렸다 피해를 주거나 이동을 멈추지 않는다. 실제 공격 시각과 시각 정점의 연동은 적용 단계에서 처리한다.
- `hurt/death`를 추가해도 피격 무적·몸체 제거 시점을 늦추지 않는다. 현재 사망한 적·좀비는 제거되므로 사망 연출은 판정 없는 표시 객체로 별도 재생해야 한다. 시체 장애물이나 경험치 드롭 지연을 만들지 않는다.

### 2.4 판정 크기와 이미지 크기

- **판정 크기**는 게임 로직에서 충돌·피격에 쓰는 사각형이다.
- **프레임 셀**은 투명 여백을 포함한 PNG 한 프레임의 전체 크기다.
- 그림의 발 중앙을 판정 사각형 하단 중앙에 맞춘다. 머리, 무기, 망토가 판정 사각형 위나 옆으로 나가는 것은 허용하지만 다른 셀을 침범하면 안 된다.
- 판정 크기를 보고 캐릭터 전체를 그 크기의 색 사각형처럼 꽉 채우지 않는다. 작은 캐릭터도 머리·몸통·다리 사이에 읽을 수 있는 음영 간격을 둔다.
- 아래 셀 크기는 적용을 쉽게 하기 위한 제작 규격이다. 임의로 캔버스 비율을 바꾸지 않는다.

좌표 원점은 셀 왼쪽 위 `(0,0)`, 오른쪽이 +X, 아래쪽이 +Y다. 아래 좌표는 픽셀 중심 인덱스가 아닌 셀 경계 기준 좌표다. 셀 크기 `W×H`인 유닛의 발 기준점은 **`(W/2,H-4)`**로 고정한다. 아래 4px은 투명 여백이고, 발이 기준선 바로 위에 접한다. 판정 크기가 `bw×bh`라면 셀 안 판정 사각형은 `(W/2-bw/2, H-4-bh, bw, bh)`다. 홀수 폭의 판정에는 0.5px 좌표가 생길 수 있으며, 이것 때문에 PNG를 반 픽셀 보간하지 않는다.

그림 배치 시 셀 왼쪽 위는 `(body.x+bw/2-W/2, body.y+bh-(H-4))`이고, 그리기 깊이는 그대로 `body.y+bh`다. **텍스처 중심이나 불투명 픽셀의 최하단으로 충돌·깊이를 다시 계산하지 않는다.** 투사체·이펙트·환경 자산의 기준점은 각 절에서 별도로 정한다.

기준색은 캐릭터 전체를 단색으로 칠하는 색이 아니라, 다수가 겹쳤을 때 종류를 알아보게 하는 핵심 포인트 색이다. 플레이어는 어두운 외투·갑주에 초자연적 포인트 색, 적은 통일된 교단 장비에 병종별 천 색을 사용한다.

## 4. 전체 자산 목록과 우선순위

- **P0:** 현재 도형을 스프라이트로 교체하기 위해 반드시 필요한 자산
- **P1:** 현재 판정을 더 잘 보여 주거나 완성도를 높이는 이펙트·추가 애니메이션
- **P2:** 현재 UI에는 없어도 되는 초상화·아이콘
- **제외:** 구현되지 않은 콘텐츠이므로 지금 만들지 않을 자산

P0 완성본은 **유닛 13종의 시트 40개 + 투사체 4개 + 구슬 색상 시트 4개 + 환경 PNG 25개 = PNG 73개**다. 유닛 시트에 들어가는 프레임은 856장이다. 개별 프레임 납품 모드에서는 이를 시트 40개와 중복 계산하지 않는다. 환경의 배치 개수와 제작 변형 수는 서로 다르다. 장애물 80개를 위해 그림 80장을 만들 필요는 없다.

외형의 선택지가 나오는 설명에는 다음 기본형을 적용해 요청마다 디자인이 바뀌지 않게 한다. 워록은 **각진 후드·왼손 마도서·오른손 시전**, 데스 나이트는 **부서진 왕관형 투구·양손 대검**, 네크로맨서는 **큰 후드·오른손 뼈 지팡이**, 좀비는 **무기 없이 양손 할퀴기**다. 병사는 **오른손 검·왼손 방패**, 기사는 **양손 대검·푸른 망토**, 성기사는 **오른손 전쟁망치·왼손 성표 방패**, 궁사는 **왼손 활·오른손 시위**, 마법사는 **오른손 수정 지팡이**, 광신도는 **양손 단검**, 석궁병은 **오른손 방아쇠·왼손 받침**, 사제는 **가슴 성표·빈 양손 축복**, 보스는 **오른손 철퇴·왼손 지휘 방패**를 쓴다. 손은 캐릭터 자신의 해부학적 좌우다. 같은 ID의 후속 요청에는 완성된 `idle_down_00`을 외형 기준 이미지로 다시 사용한다.

### 4.1 플레이어와 아군

| 우선순위 | ID | 대상 | 판정 크기 | 프레임 셀 | 필수 애니메이션 |
| --- | --- | --- | --- | --- | --- |
| P0 | `warlock` | 워록 | 40×40 | 64×64 | idle, walk, cast |
| P0 | `death_knight` | 데스 나이트 | 40×40 | 96×96 | idle, walk, attack |
| P0 | `necromancer` | 네크로맨서 | 40×40 | 64×64 | idle, walk, cast |
| P0 | `zombie` | 네크로맨서 소환 좀비 | 30×30 | 64×64 | idle, walk, attack |
| P1 | 위 4종 | 피격·사망 보완 | 위와 같음 | 위와 같음 | hurt, death |

#### 워록 `warlock`

- 역할: 빠른 연사와 다중 시전, 유도 마탄, 마력 폭발을 사용하는 사악한 주문사.
- 실루엣: 가늘고 날렵한 체형, 짧은 뿔이나 각진 후드, 찢어진 짧은 망토. 네크로맨서보다 어깨선이 날카롭고 자세가 공격적이어야 한다.
- 복장: 검푸른색 또는 흑갈색 로브 위에 에메랄드 룬이 새겨진 가죽 장식. 긴 지팡이 대신 한 손 마도서나 짧은 완드를 사용해 40×40 판정 안에서도 실루엣이 읽히게 한다.
- 얼굴: 완전히 가리지 말고 녹색으로 빛나는 눈 두 점을 남긴다.
- `cast`: 손이나 마도서에 에메랄드 에너지가 모였다가 전방으로 방출된다. 실제 투사체는 별도 자산이므로 손 앞에 큰 탄환을 그리지 않는다.
- 금지: 밝은 영웅형 마법사, 긴 흰 수염, 화려한 별무늬, 순수한 네온 녹색 면적 과다.

#### 데스 나이트 `death_knight`

- 역할: 플레이어 주변을 한 번에 베고 처치로 생명력을 빼앗는 근접 전사.
- 실루엣: 세 플레이어 중 가장 넓고 무거운 갑주, 뿔 달린 투구 또는 부서진 왕관형 투구, 한눈에 보이는 대검.
- 복장: 짙은 흑철 갑주에 뼈색 판금과 갈비뼈 모티프. 작은 핏빛 포인트는 허용하지만 워록의 초록과 네크로맨서의 청록을 빼앗지 않는다.
- 무기: 뼈색 날 또는 저주받은 흑철 대검. 방패는 사용하지 않아 원형 범위 참격의 넓은 동작을 보여 준다.
- `attack`: 몸 중심을 기준으로 넓은 원호를 긋는 횡베기. 발 위치는 고정하고, 검 끝은 셀 안에서 잘리지 않아야 한다. 실제 판정 원은 별도 이펙트로 표시한다.
- 금지: 성기사처럼 밝은 금색 갑주, 작고 가벼운 검, 해골만 둥둥 떠 있는 형태.

#### 네크로맨서 `necromancer`

- 역할: 투사체를 발사하고 시체를 좀비로 되살리는 허약한 소환사.
- 실루엣: 워록보다 굽은 자세, 길고 낡은 로브, 뼈 장식이 달린 짧은 지팡이. 가는 몸과 큰 후드로 낮은 체력을 표현한다.
- 복장: 먹빛·회청색 로브, 청록빛 회색 영혼불, 해진 소매와 작은 해골 장식.
- 얼굴: 후드 안은 어둡고 흐린 청록 눈 또는 해골 가면 일부만 보인다.
- `cast`: 지팡이를 낮게 들어 땅의 혼을 끌어올린 뒤 전방으로 작은 혼령탄을 보낸다. 좀비 소환 판정은 적 사망 시 자동으로 일어나므로 매 공격마다 좀비가 솟는 연출을 넣지 않는다.
- 금지: 워록과 같은 에메랄드 팔레트, 밝은 보라색 대마법사, 화려하고 깨끗한 왕실 로브.

#### 좀비 `zombie`

- 역할: 네크로맨서를 따라다니다 가까운 적을 물거나 할퀴는 아군 소환물.
- 실루엣: 작고 구부정한 인간형, 한쪽 어깨가 내려가고 양팔 길이가 약간 다르다. 30×30 판정에 맞게 장식은 최소화한다.
- 외형: 어두운 올리브 녹색 피부, 찢어진 회갈색 천, 흐린 청록 눈. 적 광신도와 혼동되는 주황색은 사용하지 않는다.
- `attack`: 짧게 달려들어 물거나 양손으로 할퀸다. 무기를 들지 않는다.
- 아군임을 알 수 있도록 네크로맨서와 같은 청록빛 작은 눈 또는 가슴 룬을 1~2px 넣는다.

### 4.2 일반 적과 보스

모든 적은 같은 성기사단·교단 소속처럼 보이되, 병종별 색과 무기 실루엣으로 구분한다. 일반 적의 외곽선은 짙은 녹흑색 또는 짙은 남회색으로 통일하고, 보스만 금색 외곽 장식을 더한다.

| 우선순위 | ID | 대상 | 판정 크기 | 프레임 셀 | 필수 애니메이션 |
| --- | --- | --- | --- | --- | --- |
| P0 | `soldier` | 병사 | 40×40 | 64×64 | idle, walk, attack |
| P0 | `knight` | 기사 | 80×60 | 96×80 | idle, walk, attack |
| P0 | `paladin` | 성기사 | 60×80 | 80×96 | idle, walk, attack |
| P0 | `archer` | 궁사 | 30×40 | 48×64 | idle, walk, attack |
| P0 | `mage` | 마법사 | 40×40 | 64×64 | idle, walk, cast |
| P0 | `zealot` | 광신도 | 25×30 | 48×48 | idle, walk, attack |
| P0 | `crossbowman` | 석궁병 | 40×40 | 64×64 | idle, walk, attack |
| P0 | `priest` | 사제 | 30×40 | 48×64 | idle, walk, cast |
| P0 | `commander` | 보스 성기사단장 | 70×90 | 96×112 | idle, walk, attack, cast |
| P1 | 위 9종 | 피격·사망 보완 | 위와 같음 | 위와 같음 | hurt, death |

#### 병사 `soldier`

- 가장 평범하고 자주 나오는 근접 보병이다.
- 낡은 철모, 짧은 검, 작고 각진 방패, 붉은 천 조각을 사용한다.
- 다른 병종보다 장비가 단순하고 체형이 보통이어야 한다.
- `attack`은 한 걸음 내딛는 짧은 찌르기 또는 내려베기다.

#### 기사 `knight`

- 병사보다 빠르고 강하며, 80×60의 넓은 판정이 실루엣에 드러나야 한다.
- 넓은 어깨 갑주, 큰 푸른 망토 또는 푸른 견장, 좌우로 넓은 대검 자세를 사용한다.
- 말을 탄 기사가 아니다. 인간형 중장갑이지만 몸을 낮추고 빠르게 돌진하는 느낌이다.
- `attack`은 어깨와 대검을 함께 밀어 넣는 강한 횡베기다.

#### 성기사 `paladin`

- 느리지만 매우 튼튼한 세로형 60×80 병종이다.
- 길고 무거운 금빛 성표 방패와 철퇴 또는 전쟁망치, 높은 투구로 키가 커 보이게 한다.
- 금색은 장식과 성표에 집중하고 갑주 본체는 탁한 철색으로 유지한다.
- `attack`은 방패 뒤에서 짧고 무겁게 망치를 내려치는 동작이다.

#### 궁사 `archer`

- 작고 가벼운 30×40 원거리 병종이다.
- 연두색 후드, 가죽 흉갑, 짧은 활과 등 뒤 화살통을 사용한다.
- `attack`은 활시위를 당기고 놓는 과정이 6프레임 안에서 분명해야 한다. 발사된 화살은 별도 자산이다.
- 활과 팔이 셀 경계에 닿지 않게 한다.

#### 마법사 `mage`

- 느린 보라색 원거리 주문사이며 별도 특수 능력은 없다.
- 교단 문장이 있는 짧은 보라 망토, 금속 가면, 끝에 보라 수정이 달린 지팡이를 사용한다.
- 플레이어 워록보다 자세가 엄격하고 성직자 계열로 보여야 한다.
- `cast`는 지팡이 끝에 보라 구체가 모인 뒤 발사되는 동작이다. 실제 구체는 별도 자산이다.

#### 광신도 `zealot`

- 다섯 명이 무리로 몰려오는 가장 작고 빠른 근접 적이다.
- 주황 두건, 누더기 교단복, 양손 단검 또는 한 자루의 곡선 단검을 사용한다.
- 작은 크기에서 눈과 입을 세밀하게 그리지 말고, 앞으로 기울어진 삼각형 실루엣으로 속도를 표현한다.
- `walk`는 사실상 짧은 질주처럼 보이고 `attack`은 빠른 찌르기다.

#### 석궁병 `crossbowman`

- 40×40 원거리 병종이며 궁사보다 강하고 빠른 볼트를 쏜다.
- 청록색 견장, 두 손으로 드는 큰 석궁, 짧은 철모를 사용한다.
- 활을 든 궁사와 즉시 구분되도록 가로로 넓은 석궁 실루엣을 유지한다.
- `attack`은 조준, 방아쇠, 짧은 반동이 보이게 한다. 재장전 전체를 길게 묘사할 필요는 없다.

#### 사제 `priest`

- 공격하지 않고 다른 적을 회복하는 지원 병종이다.
- 분홍빛 테두리의 회백색 성직복과 가슴의 작은 금속 성표를 사용한다.
- 무기를 들고 공격적으로 보이면 안 된다.
- `cast`는 양손을 들어 성표에 분홍빛이 켜지는 회복 동작이다. 원형 회복 범위는 별도 자산이므로 캐릭터 셀에 그리지 않는다.

#### 성기사단장 `commander`

- 게임 시간 5:00에 한 번만 등장하는 유일한 현재 보스다. 일반 성기사보다 키가 크고 지휘관 실루엣이 분명해야 한다.
- 진한 은회색 전신 갑주, 금색 테두리와 성표, 찢어진 짙은 적갈색 또는 검은 망토를 사용한다.
- 무기는 의식용 장검이나 장병기가 아니라, 96×112 셀 안에서 읽히는 큰 성광 철퇴와 지휘 방패 조합을 권장한다.
- 투구의 금빛 세로 장식과 넓은 어깨로 일반 성기사와 구분한다. 피격 시 흰색 점멸을 쓰므로 기본 몸체를 흰색으로 만들지 않는다.
- `attack`: 무거운 근접 타격.
- `cast`: 두 팔 또는 무기를 들어 고정 자세를 취하며 금색 룬이 켜진다. 아래 네 기술이 같은 기본 시전 자세를 공유해도 된다.
  - 심판의 낙인: 대상 위치에 원형 경고 후 피해.
  - 성광 십자: 보스 중심 상하좌우에 십자 경고 후 피해.
  - 기사단 소집: 주변에 병사 4명 소환.
  - 신성 방벽: 금색 보호막 전개.

### 4.3 기준점과 완성 시트 크기

`idle`은 4열, `walk/attack/cast`는 각각 6열이며 모두 4행이다. 표의 시트 크기는 **최종 PNG의 실제 픽셀 크기**다. `attack`과 `cast`는 4.1·4.2절에 지정된 것만 만들고 보스만 둘 다 만든다.

| ID | 발 기준점 | idle 시트 | walk/attack/cast 각각의 시트 |
| --- | --- | --- | --- |
| `warlock`, `necromancer`, `zombie`, `soldier`, `mage`, `crossbowman` | `(32,60)` | 256×256 | 384×256 |
| `death_knight` | `(48,92)` | 384×384 | 576×384 |
| `zealot` | `(24,44)` | 192×192 | 288×192 |
| `knight` | `(48,76)` | 384×320 | 576×320 |
| `paladin` | `(40,92)` | 320×384 | 480×384 |
| `archer`, `priest` | `(24,60)` | 192×256 | 288×256 |
| `commander` | `(48,108)` | 384×448 | 576×448 |

P1의 `hurt` 시트는 `2W×4H`, `death` 시트는 `8W×4H`다. 프레임 번호는 시트 왼쪽 위부터 행 우선 0-based로 매긴다. 방향 행 번호를 `r`, 프레임 열을 `c`, 열 수를 `N`이라 하면 **인덱스는 `r*N+c`**, 셀 왼쪽 위는 `(c*W,r*H)`다. 예: `warlock_walk`의 down은 0–5, left는 6–11, right는 12–17, up은 18–23이다.

## 5. 투사체와 수집물

투사체 스프라이트는 이동 방향에 맞춰 게임에서 회전할 수 있게 기본 방향을 **오른쪽**으로 그린다. 중심점은 캔버스 정중앙이다. 발광이 필요하면 불투명한 핵과 1~2px 반투명 가장자리만 사용한다.

이 절의 시트는 방향 행 없이 **가로 1행**이다. 4프레임 자산은 모두 64×16 PNG, 단일 화살·볼트는 24×12 PNG다. `ally_magic_bolt/mage_orb`는 12fps, 구슬은 8fps로 반복하는 제작 미리보기를 사용한다. 구슬은 회전시키지 않는다.

| 우선순위 | ID | 현재 판정 | 캔버스 | 프레임 | 설명 |
| --- | --- | ---: | ---: | ---: | --- |
| P0 | `ally_magic_bolt` | 8×8 | 16×16 | 4 | 워록·네크로맨서가 공용으로 쓸 수 있는 창백한 금빛 핵과 청록 꼬리의 마탄 |
| P0 | `archer_arrow` | 10×10 | 24×12 | 1 | 오른쪽을 향한 짧은 철촉 화살. 연두색 깃 1~2px |
| P0 | `mage_orb` | 10×10 | 16×16 | 4 | 보라색 핵이 맥동하는 작은 주문 구체 |
| P0 | `crossbow_bolt` | 10×10 | 24×12 | 1 | 화살보다 굵고 짧은 철제 볼트. 청록색 깃 |
| P0 | `exp_orb` | 12×12 | 16×16 | 4 | 마름모형 경험치 결정. 반짝임 애니메이션 |
| P1 | `warlock_bolt` | 8×8 | 16×16 | 4 | 공용 마탄을 나눌 경우 사용할 에메랄드 룬탄 |
| P1 | `necromancer_bolt` | 8×8 | 16×16 | 4 | 공용 마탄을 나눌 경우 사용할 청록빛 작은 혼령탄 |

게임은 직업 전용 탄환을 우선하고, 없으면 `ally_magic_bolt`를 공용 예비로 쓴다. 현재 `warlock_bolt`만 제공되어 네크로맨서는 공용 마탄을 쓴다. `necromancer_bolt`를 제공하면 13절대로 가공하고 직업별 마탄 표에 연결한다.

- 16×16의 발광탄 핵은 셀 중앙 `(8,8)`에 두고 꼬리는 왼쪽으로 뻗는다. 화살·볼트는 `(12,6)`을 회전 기준점으로 삼고 중심축은 `y=6`이다. 핵이나 몸통 중심이 앞으로 쏠려 회전할 때 궤도가 흔들리지 않게 한다.
- 화살·볼트의 그림은 가로로 길어도 현재 피격 판정은 축에 정렬된 정사각형이다. PNG의 길이를 판정 폭으로 쓰거나 판정까지 회전하지 않는다. 로직의 발사 위치는 몸체 중심이며 손·지팡이 끝으로 판정을 옮기는 변경은 포함하지 않는다.
- 적 `Projectile`은 표시 전용 `source`에 쏜 병종을 담고, 게임은 이 값으로 화살·구체·볼트를 고른다. 파일명만으로 자동 분기되지 않으므로 새 원거리 병종은 병종별 투사체 표에 연결한다.

## 6. 전투 이펙트와 위험 표시

위험 범위는 판정과 정확히 일치해야 하므로 빨간 원·십자 경고와 금색 방벽 범위는 코드의 기하 도형을 유지하는 것이 안전하다. 아래 이펙트는 그 도형을 가리지 않는 장식 오버레이로 만든다. 불투명한 연기나 섬광으로 캐릭터를 완전히 덮지 않는다.

| 우선순위 | ID | 기준 범위 | 규격 | 프레임 | 시각 지시 |
| --- | --- | --- | --- | ---: | --- |
| P1 | `death_slash` | 기본 반경 100px, 성장 시 확대 | 128×128 정규화 | 4 | 연보라 `#c9b8ff` 원호, 중심은 투명 |
| P1 | `magic_explosion` | 중첩당 반경 20px | 96×96 정규화 | 4 | 주황 `#ffa64d` 룬 파열, 바깥쪽으로 퍼짐 |
| P1 | `corpse_blast` | 반경 80px | 160×160 | 6 | 연두 `#8fd16a` 독기와 뼛조각, 잔혹한 피 표현은 최소화 |
| P1 | `priest_heal` | 반경 160px | 192×192 정규화 | 6 | 분홍 `#e58fb8` 성표와 위로 오르는 빛 입자 |
| P1 | `boss_brand_impact` | 반경 100px | 200×200 | 6 | 붉은 경고 원 안에서 금빛 낙인이 닫히는 타격 |
| P1 | `boss_cross_impact` | 폭 60px, 중심에서 각 방향 500px | 60×128 반복 세그먼트 | 6 | 창백한 금빛 성광. 세로 세그먼트를 회전·반복 가능하게 제작 |
| P1 | `boss_aegis` | 반경 160px | 192×192 정규화 | 6 | 금색 원형 룬과 얇은 방벽 조각. 중앙은 투명 |
| P1 | `raise_zombie` | 좀비 생성 지점 | 64×64 | 6 | 흙먼지와 청록 혼불. 좀비 본체나 손은 그리지 않아 실제 소환물과 중복되지 않게 함 |

- 정규화 자산은 게임에서 실제 반경에 맞게 균일 확대·축소한다.
- 보스 경고 자체는 붉은 반투명 도형으로 남기고, 이펙트는 피해 순간에만 더한다.
- 데스 나이트 공격 반경은 특기로 계속 커질 수 있으므로 검 그림 한 장에 고정 반경을 박지 않는다.
- 단발 이펙트의 첫·마지막 프레임은 투명하고 중간 프레임에서 형태가 가장 명확해야 한다. **지속 반복형 `boss_aegis`는 예외**이며 첫·끝이 같은 밝기와 룬 위치로 이어져 방벽이 주기적으로 꺼져 보이지 않게 한다.

### 6.1 배열·크기·재생 시간

모두 방향 구분 없이 가로 1행이다. 정사각형 효과의 기준점은 셀 중앙이다. 반경 `r`인 효과는 셀 너비 `W`에 대해 배율 `2*r/W`로 균일 확대하며, 중심을 효과의 월드 좌표에 맞춘다. 중앙에는 유닛을 읽을 수 있는 투명 공간을 남긴다. 픽셀 밀도가 달라지는 범위 확대는 이 장식 이펙트에만 허용하고 정확한 외곽은 코드 도형으로 유지한다.

| ID | 완성 PNG | 재생 방식 | 시간 기준 |
| --- | --- | --- | --- |
| `death_slash` | 512×128 | 4장 단발 | 현재 효과 수명 전체에 맞춤 |
| `magic_explosion` | 384×96 | 4장 단발 | 현재 효과 수명 전체에 맞춤 |
| `corpse_blast` | 960×160 | 6장 단발 | 현재 효과 수명 전체에 맞춤 |
| `priest_heal` | 1152×192 | 6장 단발 | 현재 효과 수명 전체에 맞춤 |
| `boss_brand_impact` | 1200×200 | 6장 단발 | 장식 미리보기 300ms |
| `boss_cross_impact` | 360×128 | 6장 단발 | 장식 미리보기 300ms |
| `boss_aegis` | 1152×192 | 6장 반복 | 12fps, 방벽 활성 동안만 표시 |
| `raise_zombie` | 384×64 | 6장 단발 | 장식 미리보기 300ms |

현재 `swing/explosion/blast/heal` 기록의 수명은 `SKILL_CONFIG.effectMs`의 **150ms**다. 4장은 장당 37.5ms, 6장은 장당 25ms로 전체 재생한다. 유닛용 12fps를 적용하면 끝까지 재생하기 전에 사라지므로 사용하지 않는다. 게임 시간의 진행 비율로 프레임을 정하고 보상 선택으로 일시정지되면 함께 정지한다. 피해·회복 시각과 효과 수명은 그대로 유지한다.

보스 타격 2종과 좀비 부활은 표시 전용 효과 기록(`brand`·`cross`·`raise`)으로 경고가 해결되는 순간의 좌표와 부활한 좀비의 발밑을 전달하며, 수명은 `SKILL_CONFIG.impactMs` 300ms다. 판정 지연이 아니다. 사제 회복은 실제로 회복한 대상이 있을 때만, 시체 폭발은 해당 특기가 있는 좀비가 죽을 때만 표시한다. 기사단 소집은 기존 `soldier`를 재사용하며 별도 병사·시체 스프라이트를 만들지 않는다.

### 6.2 성광 십자 연결 규격

`boss_cross_impact`는 세로로 긴 **폭 60×높이 128** 셀이다. 각 프레임의 위·아래 가장자리 패턴이 이어지게 하고 좌우는 투명하다. 가로 팔은 같은 프레임을 90° 회전해 쓴다. 실제 십자는 길이 500px짜리 한 줄이 아니라, 중심에서 양쪽으로 500px씩 뻗는 **1000×60 가로 사각형과 60×1000 세로 사각형의 합집합**이다. 반복 후 양 끝을 정확한 길이로 자르고 중앙 겹침은 한 번만 합성해 밝기가 두 배가 되지 않게 한다. 폭을 늘려 맞추거나 프레임마다 다른 반복 위상을 쓰지 않는다. 이 연결 처리는 표시용이며 판정 사각형을 바꾸지 않는다.

## 7. 월드와 장애물

### 7.1 바닥 타일과 통과 가능한 장식

| 우선순위 | ID | 크기 | 수량 | 지시 |
| --- | --- | ---: | ---: | --- |
| P0 | `ground_dead_earth` | 128×128 | 4 변형 | 이음새 없는 어두운 흙, 회갈색 명암, 저대비 입자. 네 변이 자연스럽게 연결되어야 함 |
| P0 | `decal_dry_grass` | 32×32 | 6 변형 | 채도 낮은 마른 풀과 잿빛 이끼, 투명 배경 |
| P0 | `decal_twig` | 32×32 | 6 변형 | 작은 마른 가지와 부러진 잔가지, 투명 배경 |
| P1 | `decal_pebble` | 24×24 | 4 변형 | 낮고 작은 돌·흙덩이, 충돌물처럼 커 보이지 않게 함 |

- 바닥 타일 중앙에 해골, 큰 룬, 길, 웅덩이처럼 반복이 눈에 띄는 랜드마크를 넣지 않는다.
- 타일 가장자리의 색과 무늬가 반대편 가장자리와 정확히 이어져야 한다.
- 네 변형은 같은 팔레트와 공통 가장자리 띠를 사용해 **자기 자신뿐 아니라 서로 다른 변형끼리도** 상하좌우로 이어져야 한다. 가장자리 2px 띠는 같은 좌표의 색·패턴으로 맞추고 차이는 내부 저대비 입자에만 둔다. 바닥은 alpha=255인 불투명 PNG다.
- 장식은 플레이어가 통과하므로 높이가 있는 장애물처럼 강한 그림자나 큰 실루엣을 만들지 않는다.
- 바닥·장식의 기준점은 왼쪽 위 `(0,0)`이다. 각각의 변형은 시트가 아닌 독립 PNG로 저장한다. 현재 바닥은 월드 전체의 절차적 텍스처 한 장이므로 타일 반복과 장식 배치는 적용 단계에서 연결해야 한다.

### 7.2 울타리

| 우선순위 | ID | 크기 | 지시 |
| --- | --- | ---: | --- |
| P0 | `gothic_fence` | 100×50 | 좌우로 반복 가능한 철제 울타리. 첨두 아치, 창살, 작은 십자 장식, 녹슨 철, 왼쪽 끝 석재 연결 기둥 |
| P0 | `fence_corner` | 50×50 | 위에서 본 정사각 석재 모서리 기둥. 중앙에 닳은 십자 금속 장식 |

- 울타리는 월드 네 변에서 회전해 사용한다. 회전했을 때도 한쪽에만 강한 그림자가 생겨 방향이 어색하지 않게 한다.
- `gothic_fence`의 좌우 끝은 반복 시 이음새가 없어야 한다.
- 울타리 전체 높이 50px 안에서 아래쪽 6~10px은 단단한 기반, 위쪽은 철창 실루엣으로 구성한다.
- 울타리·모서리 기둥의 배치 기준점은 각각 중앙 `(50,25)`, `(25,25)`이다. 현재 울타리는 50px 두께 영역 안에서 반복·회전되며 유닛보다 아래에 그려진다. 유닛 앞을 덮는 높은 담장처럼 만들지 않는다.
- 울타리 이음부의 수평 난간 높이·두께를 양 끝에서 일치시킨다. 기둥은 모듈 왼쪽에 한 번만 넣고 오른쪽에는 같은 기둥을 중복하지 않는다. 회전·반전을 사용하는 환경 자산에는 공통 달빛을 약하게 적용해 어느 방향에서도 과도한 명암 차이가 나지 않게 한다.

### 7.3 충돌 장애물

모든 좌표는 이미지 왼쪽 위 기준이다. **충돌 영역에는 중요한 받침대·바위·뿌리가 들어가야 하고, 충돌 영역 위쪽의 비석 몸체나 나뭇가지는 캐릭터가 뒤로 지나가며 가려지는 부분**이다.

| 우선순위 | ID | 이미지 크기 | 이미지 안 충돌 영역 `(x, y, w, h)` | 현재 배치 수량 | 지시 |
| --- | --- | ---: | --- | ---: | --- |
| P0 | `grave` | 96×96 | `(22, 28, 52, 54)` | 6 | 온전하지만 금이 간 둥근 비석, 작은 십자 음각, 이끼 낀 받침대 |
| P0 | `cross_grave` | 96×96 | `(22, 28, 52, 54)` | 10 | 닳고 금이 간 석재 십자가, 낮은 받침대 |
| P0 | `broken_grave` | 96×96 | `(14, 34, 66, 50)` | 16 | 위가 불규칙하게 부서진 비석과 옆에 떨어진 파편 |
| P0 | `rock` | 96×96 | `(10, 28, 78, 54)` | 16 | 낮고 넓은 회녹색 바위, 한쪽 균열과 약한 이끼 |
| P0 | `stump` | 96×96 | `(14, 14, 68, 74)` | 8 | 뿌리가 벌어진 썩은 그루터기, 잘린 나이테 |
| P0 | `log` | 96×96 | `(4, 40, 88, 42)` | 16 | 가로로 쓰러진 통나무, 한쪽 잘린 단면, 작은 부러진 가지 |
| P0 | `dead_tree` | 108×120 | `(20, 64, 68, 46)` | 8 | 잎 없는 굽은 나무, 갈라진 가지, 노출된 뿌리. 위쪽 가지 뒤로 캐릭터가 지나감 |

- 장애물은 모두 바닥 중앙에 놓인 독립 PNG이고 배경은 투명하다.
- 장애물은 유닛의 아래 4px 기준을 사용하지 않는다. 그림의 접지 기준점은 아래 표처럼 **충돌 사각형 하단 중앙**이다. 위쪽 장식은 영역 밖으로 나갈 수 있지만 뿌리·받침대를 이 기준보다 아래로 내려 접지 위치를 바꾸지 않는다.
- 좌우 반전해서도 사용할 수 있도록 한쪽에만 글자·문장·광원·긴 그림자를 넣지 않는다.
- P0에서는 종류별 한 장이면 충분하다. 반복감 개선용 2~3개 변형은 P1이며, 변형을 만들 때도 이미지 크기와 충돌 영역을 바꾸지 않는다.
- 외부 참고 이미지나 `sample_image/` 경로의 파일 첨부는 필수가 아니다. 본문 설명만으로 제작한다. 사용자가 별도 참고를 제공하면 재질·구조만 참고하고 그대로 복제하지 않는다.

| ID | 접지 기준점 | 코드의 종류 ID |
| --- | --- | --- |
| `grave` | `(48,82)` | `grave` |
| `cross_grave` | `(48,82)` | `cross-grave` |
| `broken_grave` | `(47,84)` | `broken-grave` |
| `rock` | `(49,82)` | `rock` |
| `stump` | `(48,88)` | `stump` |
| `log` | `(48,82)` | `log` |
| `dead_tree` | `(54,110)` | `dead-tree` |

표의 충돌 좌표는 **좌우 반전 전 원화** 기준이다. 좌우 반전 시 폭 `W`인 PNG 안의 충돌 X는 `W-x-w`가 된다. 접지점이 `(47,84)`인 부서진 비석을 임의로 `(48,84)`에 재정렬하지 않는다. 현재 `getObstacleVisual`은 이미지 중심이 아니라 **월드 충돌 사각형 중심**에 맞춰 반전 이미지의 배치 위치를 보정한다. 이 계산과 기존 충돌 좌표를 유지해야 비대칭 비석·바위의 받침대가 어긋나지 않는다.

## 8. 현재 만들지 않을 것

다음 항목은 현재 구현에 필요하지 않거나 아직 설계가 확정되지 않았다. 첫 제작 묶음에 포함하지 않는다.

- 보류 직업 드라큘라, 드루이드, 서큐버스
- 보류 보스 용사
- 새로운 적, 상점, 보물상자, 무기 드롭, 펫
- 레벨업 보상별 아이콘과 가호 아이콘
- 타이틀 로고 일러스트와 배경 일러스트
- HUD 패널, 버튼, 카드 프레임, 글꼴
- 피, 절단, 시체 더미 같은 고어 장식
- BGM과 효과음

현재 캐릭터 선택 화면에는 별도 초상화가 필요하지 않다. 각 플레이어의 `idle_down` 첫 프레임을 카드 미리보기로 재사용할 수 있다. 256×256 초상화는 UI 개편이 결정된 뒤 P2로 제작한다.

## 9. 파일 이름과 권장 폴더

파일 이름 본문은 **영문 소문자·숫자·밑줄**만 사용하고 확장자는 `.png`다. 최종 파일은 아래 경로에 두며 `public/`은 브라우저 URL에 포함하지 않는다. 이는 적용 시 사용할 폴더 규약이며 현재 로더가 이 경로를 자동으로 읽는다는 의미는 아니다.

```text
public/assets/sprites/
  characters/
    warlock_idle.png
    warlock_walk.png
    warlock_cast.png
    death_knight_idle.png
    ...
  enemies/
    soldier_idle.png
    soldier_walk.png
    soldier_attack.png
    ...
    commander_cast.png
  summons/
    zombie_idle.png
    ...
  projectiles/
    ally_magic_bolt.png
    archer_arrow.png
    mage_orb.png
    crossbow_bolt.png
  pickups/
    exp_orb_blue.png
    exp_orb_green.png
    exp_orb_gold.png
    exp_orb_red.png
  effects/
    death_slash.png
    magic_explosion.png
    ...
  world/
    ground_dead_earth_01.png
    decal_dry_grass_01.png
    gothic_fence.png
    fence_corner.png
    obstacle_grave.png
    obstacle_cross_grave.png
    ...
```

### 9.1 누락 없이 파일 이름 정하기

| 폴더 | 제작 ID | 파일 이름 규칙 |
| --- | --- | --- |
| `characters/` | `warlock`, `death_knight`, `necromancer` | `{id}_{animation}.png` — 4.1절의 애니메이션만 |
| `summons/` | `zombie` | 위와 같음 |
| `enemies/` | `soldier`, `knight`, `paladin`, `archer`, `mage`, `zealot`, `crossbowman`, `priest`, `commander` | 위와 같음 |
| `projectiles/` | `ally_magic_bolt`, `archer_arrow`, `mage_orb`, `crossbow_bolt` | `{id}.png` |
| `pickups/` | `exp_orb` | `exp_orb_blue.png`, `exp_orb_green.png`, `exp_orb_gold.png`, `exp_orb_red.png` |
| `world/` | `ground_dead_earth` | `ground_dead_earth_01.png` ~ `ground_dead_earth_04.png` |
| `world/` | `decal_dry_grass`, `decal_twig` | 각각 `{id}_01.png` ~ `{id}_06.png` |
| `world/` | `gothic_fence`, `fence_corner` | `{id}.png` |
| `world/` | 7종 장애물 | `obstacle_{id}.png` — 7.3절 ID 사용 |
| `effects/` | 6절의 P1 효과 | `{id}.png` |

P1을 별도로 요청하면 전용 마탄은 `projectiles/warlock_bolt.png`, `projectiles/necromancer_bolt.png`, 작은 돌 장식은 `world/decal_pebble_01.png` ~ `04.png`로 저장한다. 장애물 변형은 기본 파일을 유지하고 `world/obstacle_{id}_02.png`, `_03.png`를 추가한다. 유닛의 `hurt/death`도 기존 `{id}_{animation}.png` 규칙을 따른다. 이 파일들은 P0의 73개에 포함하지 않는다.

개별 프레임 모드에서는 중간 파일을 `raw/{folder}/{id}_{animation}_{direction}_{index}.png`에 두고 인덱스는 `00`부터 두 자리로 쓴다. 예: `raw/characters/warlock_walk_left_03.png`. 방향이 없는 자산은 방향 토큰을 빼서 `raw/projectiles/ally_magic_bolt_00.png`처럼 쓴다. 환경 정지 PNG는 최종 파일명을 그대로 쓴다. 시트 포장 전 프레임은 각각 원래 셀 크기를 유지한다. 원본·검수용 배경 합성본은 최종 폴더에 섞지 않는다.

### 9.2 제작 ID와 코드 ID 대응

- 플레이어 `death_knight`의 실제 `CharacterId`는 **`deathKnight`**다. 나머지 플레이어와 적 ID는 이름이 같다.
- 장애물의 밑줄 ID와 하이픈 코드 ID는 7.3절 표를 따른다. 현재 텍스처 키는 `obstacle-${kind}`이며 예를 들어 `obstacle-cross-grave`가 `world/obstacle_cross_grave.png`에 대응한다.
- 환경 코드 텍스처 키 `dead-ground/gothic-fence/fence-corner`는 각각 바닥/울타리/모서리에 대응한다. 바닥은 현재 한 장이므로 4종 타일을 사용하려면 반복 배치를 추가해야 한다.
- 효과 기록 `swing/explosion/blast/heal`은 각각 `death_slash/magic_explosion/corpse_blast/priest_heal`에 대응한다. 파일 ID를 전투 로직의 종류 ID로 바꾸지 않는다.

### 9.3 납품 메타데이터

PNG와 함께 같은 이름의 `.json`을 제공한다. 다음은 **완성된 `warlock_walk.png`**의 예다. 알파·셀·좌표를 실제 검사한 뒤에만 `ready`를 쓴다.

```json
{
  "asset_id": "warlock",
  "code_id": "warlock",
  "animation": "walk",
  "file": "characters/warlock_walk.png",
  "texture_key": "warlock_walk",
  "frame_size_px": [64, 64],
  "sheet_size_px": [384, 256],
  "directions": ["down", "left", "right", "up"],
  "frames_per_direction": 6,
  "frame_count": 24,
  "margin_px": 0,
  "spacing_px": 0,
  "anchor_kind": "foot",
  "anchor_px": [32, 60],
  "body_rect_px": [12, 20, 40, 40],
  "preview_fps": 10,
  "loop": true,
  "background": "transparent",
  "alpha_mode": "binary",
  "trimmed": false,
  "status": "ready"
}
```

`file`은 `public/assets/sprites/` 기준 상대 경로다. 방향 없는 자산은 `directions: []`, `frames_per_direction` 대신 `frames_per_row`와 전체 `frame_count`를 기록한다. 투사체·구슬·효과·울타리·모서리 기둥은 `anchor_kind: center`, 바닥·통과 장식은 `top_left`, 장애물은 `foot`과 7.3절 접지점을 쓴다. 장애물의 `body_rect_px`는 그 절의 충돌 영역이다. 표시용 이펙트에는 `body_rect_px`를 넣지 않는다. 바닥은 `background: opaque`, `alpha_mode: opaque`를 기록하고 마법 투사체·효과는 `alpha_mode: partial`을 허용한다. 효과에는 `preview_duration_ms` 또는 반복 fps와 `loop`를 기록한다.

전체 묶음을 납품할 때는 `manifest.json`에 각 메타데이터를 배열로 모으고, P0의 73개 최종 경로에 대한 완료·미완료 목록을 함께 제공한다. `raw`만 있는 항목은 완료로 세지 않는다.

## 10. AI에 전달할 작업 방식

아래 순서로 생성하고 각 묶음의 규격을 검수한다. 앞 단계의 팔레트·외곽선·광원·픽셀 밀도를 이후 단계에서도 그대로 유지한다. 화풍 기준 이미지를 후속 요청에 함께 전달하면 인물·장비가 달라지는 것을 줄일 수 있다. 기준 이미지가 없어도 본문의 기본형으로 제작할 수 있어야 한다.

1. 워록 `idle_down` 단일 프레임, 병사 `idle_down` 단일 프레임, 온전한 비석 한 장으로 화풍 시험본을 만든다.
2. 시험본 검수 후 플레이어 3종과 좀비의 P0 애니메이션을 만든다.
3. 일반 적 8종의 P0 애니메이션을 만든다.
4. 성기사단장 P0 애니메이션을 만든다.
5. 투사체와 경험치 구슬을 만든다.
6. 바닥·울타리·장애물을 만든다.
7. P1 전투 이펙트와 hurt/death 애니메이션을 만든다.

AI는 매 요청마다 아래 순서로 응답한다.

1. 만들 대상의 ID, 캔버스, 방향, 프레임 수를 한 줄로 확인한다.
2. 이 문서의 공통 화풍과 해당 대상 지시를 적용한다.
3. 지정된 PNG 또는 개별 프레임을 생성한다.
4. 누락된 방향, 잘린 픽셀, 불투명 배경, 셀 크기 불일치가 없는지 자체 점검한다.
5. 파일명과 프레임 배열 정보를 함께 제시한다.

아래 프롬프트들은 **이 문서 전체와 함께 전달하는 작업 지시**다. 일부 블록만 따로 전달한다면 2절 공통 규칙과 해당 자산의 외형·규격도 함께 포함한다. 경로·파일명을 텍스트에 쓰는 것만으로 납품이 완료되지는 않으며 실제 PNG 파일을 제공해야 한다.

### 10.1 기본 실행: 워록 화풍 시험본

```text
이 문서의 제작 규격에 따라 warlock의 idle, down 방향, 0번 프레임 한 장을 실제 생성하라.
파일명 warlock_idle_down_00.png, 최종 64x64 RGBA PNG, 물체 밖 완전 투명.
탑다운 3/4 앞모습, 발 기준점 (32,60), 아래 4px 투명, 셀 안 판정 참고 영역 (12,20,40,40).
가늘고 날렵한 사악한 주문사, 각진 검푸른 후드와 짧고 찢어진 망토,
에메랄드 #66ddaa 룬, 녹색 눈 두 점, 캐릭터 왼손 마도서와 오른손 시전 자세.
최종 해상도 1px 단위 픽셀 아트, 1~2px 외곽선, 명암 3~5단계, 약한 왼쪽 위 달빛.
그림자, 원형 후광, 바닥, 글자, 워터마크, 안티앨리어싱, 흐림, 반투명 테두리는 금지.
큰 이미지나 합본을 완성본으로 제출하지 말고 지정 크기 파일과 검사 결과를 제공하라.
정확한 픽셀 크기 또는 알파를 확인할 수 없다면 raw로 표시하고 미확인 항목을 적어라.
이 한 장은 화풍 기준이며 4방향 idle 완성 시트로 세지 않는다.
```

같은 단계의 나머지 시험본은 `soldier_idle_down_00.png`(64×64, 발 `(32,60)`, 오른손 검·왼손 방패·붉은 천)와 `obstacle_grave.png`(10.6절)다. 한 요청에서 한 자산씩 만든다.

### 10.2 유닛 애니메이션 시트

```text
제작 대상: warlock_walk.png 한 장. 이 문서 2·3·4절과 완성된 기준 이미지의 외형을 유지하라.
프레임 64x64, 발 (32,60), 6열 x 4행, 최종 PNG 384x256, 총 24프레임이다.
행은 down,left,right,up이며 열은 보행 시간 순서 00~05다. 간격·외부 여백은 0이다.
10fps 반복 보행, 마지막에서 처음으로 부드럽게 연결하며 첫 프레임을 끝에 복제하지 않는다.
네 방향 모두 같은 왼손 마도서·오른손, 같은 옷·체형·왼쪽 위 광원을 유지하라.
각 셀의 크기·접지점·픽셀 밀도를 고정하고 자동 트리밍하지 않는다.
정확한 시트 제작이 어려우면 warlock_walk_{direction}_{00~05}.png 24개를
각각 64x64로 제공하고 포장 전 raw임을 표시하라. 파일과 9.3절 메타데이터를 제공하라.
```

다른 유닛은 ID·애니메이션을 4절에서 고르고 셀·발·최종 시트 크기를 해당 표의 값으로 바꾼다. `attack/cast`는 2.3절의 준비·정점·복귀 순서를 사용하며 공격 판정이나 투사체를 캐릭터 셀에 그리지 않는다. 예: 보스 `commander_cast.png`는 96×112 셀, 발 `(48,108)`, 6열×4행, **576×448**, 24장이다. 네 보스 기술이 한 시전 시트를 공유한다.

### 10.3 투사체

```text
제작 대상: projectiles/ally_magic_bolt.png 한 장.
16x16 셀 4개를 가로 1행, 최종 64x16 RGBA PNG, 기준점은 각 셀 (8,8)이다.
오른쪽을 향한 창백한 금빛 핵과 청록 꼬리를 그려라. 핵은 중앙, 꼬리는 왼쪽이다.
12fps 반복 시 맥동이 연결되어야 하며 셀마다 핵 위치·크기·방향을 바꾸지 않는다.
불투명한 핵과 최대 1~2px 반투명 가장자리만 허용하고 배경은 완전 투명하게 한다.
방향 행, 발사하는 인물, 폭발, 바닥, 글자를 추가하지 않는다. 실제 판정은 8x8로 유지한다.
```

화살·볼트는 5절에 따라 각각 24×12의 단일 PNG이며 날아가는 방향은 오른쪽이다. `mage_orb`는 같은 4열 배열의 보라 구체다. 투사체끼리 한 시트로 합치지 않는다.

### 10.4 경험치 4색 묶음

```text
제작 대상: exp_orb_blue/green/gold/red.png 네 장. 각 PNG는 16x16 셀 4개, 가로 1행 64x16이다.
중심 (8,8), 중앙 12x12 안에서 읽히는 마름모 결정, 8fps 반복 반짝임으로 그려라.
색은 blue #6fb8ff, green #7ee08c, gold #ffd65a, red #ff7a6b를 각각 기준으로 쓴다.
네 파일의 프레임별 실루엣·위치·음영 단계는 동일하고 팔레트만 바꾼다.
물체 밖 alpha=0, 결정 alpha=255, 바깥 후광 없이 완성 PNG 네 개를 별도로 제공하라.
```

### 10.5 바닥·통과 장식

```text
제작 대상: ground_dead_earth_01.png~04.png, 독립된 128x128 PNG 네 장.
이 자산만 배경까지 모두 불투명 alpha=255이며 투명 구멍이 없어야 한다.
#24231f와 #302b25 중심의 저대비 죽은 흙, 회갈색 입자, 큰 랜드마크 없는 픽셀 아트다.
네 변형의 가장자리 2px 띠를 공통으로 맞춰 어떤 두 변형도 상하좌우로 연결되게 하라.
내부 입자만 다르게 하고 바둑판 경계·반복되는 큰 바위·풀·문양·그림자를 넣지 않는다.
원본 네 PNG와 별도의 2x2 반복 검수 미리보기를 제공하라. 미리보기를 타일 파일로 제출하지 않는다.
```

통과 장식은 바닥을 포함하지 않은 투명 PNG다. `decal_dry_grass_01`~`06`, `decal_twig_01`~`06`을 각각 32×32로 만들고, 밟고 지나갈 수 있는 낮고 저대비인 풀·가지만 그린다.

## 11. 납품 전 체크리스트

검수는 메타데이터의 자기 보고뿐 아니라 실제 PNG와 재생 미리보기로 수행한다. 형식 검사와 시각 검사를 모두 통과한 파일만 `ready`다. 불일치·미확인 항목은 파일별로 기록하고 수정할 파일을 특정한다.

### 모든 이미지

- [ ] 실제 파일 헤더가 PNG, RGBA 채널당 8-bit이며 실제 가로·세로가 규격과 같은가?
- [ ] 바닥은 전 픽셀 alpha=255이고, 나머지는 물체 밖 alpha=0인가? 체크무늬가 합성되어 있지 않은가?
- [ ] 비마법 자산은 알파가 0/255뿐이며, 반투명은 지정한 마법 투사체·효과에만 있는가?
- [ ] 안티앨리어싱, 흐림, 불필요한 반투명 테두리가 없는가?
- [ ] 파일 이름에 공백·한글·대문자가 없는가?
- [ ] 다른 프레임이나 셀을 침범한 픽셀이 없는가?
- [ ] 화면 왼쪽 위 광원과 제한 팔레트가 유지되는가?
- [ ] 검수용 흰 배경과 어두운 `#24231f` 배경 양쪽에서 가장자리가 깨끗한가? 배경 합성본은 최종 PNG와 분리했는가?
- [ ] 메타데이터의 실제 경로·크기·프레임 수·기준점이 파일과 일치하며 트리밍되지 않았는가?

### 캐릭터와 적

- [ ] 4개 행이 down, left, right, up 순서인가?
- [ ] `idle` 16장, `walk/attack/cast` 각각 24장이 빠짐없이 있으며 의도치 않은 빈 셀·중복 셀이 없는가?
- [ ] 모든 프레임에서 발 기준점이 같은가?
- [ ] idle과 walk가 자연스럽게 반복되는가?
- [ ] 네 방향의 얼굴·체형·주무기·방패 손과 복장 손상이 동일한가?
- [ ] 무기·망토가 프레임 밖으로 잘리지 않는가?
- [ ] 1280×720 화면에서 원본 크기로 보았을 때 병종을 구분할 수 있는가?
- [ ] 플레이어와 적, 좀비와 광신도를 색과 실루엣으로 즉시 구분할 수 있는가?
- [ ] 4색 경험치 구슬의 프레임별 형태는 같고 팔레트만 다른가?

### 환경

- [ ] 바닥 4종을 각각 2×2 반복하고, 서로 다른 타일의 모든 조합을 상하·좌우로 붙였을 때 이음새가 없는가?
- [ ] 통과 장식과 충돌 장애물의 시각적 무게가 구분되는가?
- [ ] 장애물의 받침대·뿌리가 지정된 충돌 영역 안에 있는가?
- [ ] 비석 상단과 나뭇가지 뒤로 캐릭터가 지나가도 자연스러운가?
- [ ] 좌우 반전해도 빛과 형태가 심하게 어색하지 않은가?
- [ ] 울타리를 3개 이상 이어 붙이고 0/90/180/270°로 배치해도 난간·기둥이 연결되는가?
- [ ] 장애물을 충돌 중심으로 반전해도 받침대와 실제 판정이 일치하는가?

### 이펙트

- [ ] 판정 경고 도형을 가리지 않는가?
- [ ] 단발 효과의 첫·마지막은 투명하고, 지속형 방벽은 첫·끝이 이어지는가?
- [ ] 현재 효과 4종을 150ms로 재생해도 정점이 보이고 끝까지 재생되는가?
- [ ] 반복 세그먼트는 이어 붙였을 때 경계가 보이지 않는가?
- [ ] 십자 교차점의 중복 광채와 양 끝의 초과 길이가 없는가?
- [ ] 과도한 광채 때문에 작은 캐릭터 실루엣이 사라지지 않는가?

검수 미리보기는 셀을 분할한 정지 배열과 실제 재생을 모두 제공한다. 정지 배열에만 방향·번호·판정 가이드를 표시할 수 있다. 이러한 가이드를 최종 PNG에 합성하지 않는다. 생성 도구가 미리보기를 지원하지 않으면 미검수로 기록한다.

## 12. 게임 적용 시 연결할 위치

이 절은 제작 파일을 넘겨받는 개발자용이다. **세 직업·좀비·적 9종·투사체·경험치 구슬·전투 효과의 로드·표시 연결은 완료했다.** 바닥·울타리·장애물은 아직 코드 텍스처이며, 파일을 올려놓는 것만으로 교체되지는 않는다. 게임 규칙·공격 간격·판정·장애물 배치를 바꾸지 않고 표시 계층을 연결한다.

| 코드 | 현재 표시 | 적용 시 연결 |
| --- | --- | --- |
| [main.ts](../src/main.ts) `GameScene.preload/create/syncBattle` | 세 직업·좀비·적 9종·투사체·구슬·효과 PNG, 범위 원·보스 경고 도형 | 공통 설정·재생기로 연결 완료. 외형이 정해지지 않은 투사체는 병종 색 사각형으로 대체(폴백) |
| [menu-scenes.ts](../src/menu-scenes.ts) `CharacterSelectScene` | 직업별 정면 대기 PNG | 세 직업 모두 몸체·마법/검격 첫 프레임 재사용, 별도 초상화 불필요 |
| [dungeon.ts](../src/dungeon.ts) `createDungeon` | 작은 코드 텍스처를 2배 표시 | 최종 크기의 장애물 PNG는 **배율 1**, `getObstacleVisual` 위치·반전·깊이는 유지 |
| [world-art.ts](../src/world-art.ts) `decorateWorld` | 월드 전체 바닥, 반복 울타리·모서리 | 128px 바닥 타일 배치·통과 장식 연결, 울타리·모서리는 현재 크기로 사용 |
| [battle.ts](../src/battle.ts) | 공격·소환·보스 판정과 표시 전용 기록(`playerAction`·`action`·`source`·`effects`) | 연결 완료. 새 외형이 판정 정보를 더 필요로 할 때만 표시 전용 기록을 추가 |
| [render-depth.ts](../src/render-depth.ts) `getFootDepth` | 몸체 하단 기준 깊이 | 유닛·장애물의 기존 계산 유지 |

유닛의 표시 위치는 `(body.x+body.width/2, body.y+body.height)`, Phaser origin은 `(anchorX/W, anchorY/H)`다. 반면 투사체·구슬·원형 범위 효과의 표시 위치는 **판정 몸체 또는 효과의 중심**이다. 유닛 스프라이트의 발 위치를 그대로 공격 원의 중심으로 쓰면 기존 판정에서 아래로 어긋난다. 투사체의 회전 각도는 `atan2(vy,vx)`이며 정사각 판정은 그대로 둔다.

표시 순서는 현재처럼 바닥·울타리 → 구슬/유닛/장애물의 발밑 깊이 → 보스 경고·방벽 → 투사체 → 단발 범위 효과 → HUD·선택창이다. 새 장식 효과가 빨간 경고선이나 HUD를 덮지 않게 한다. 애니메이션은 실제 시간 대신 게임 시간으로 진행해 보상 선택과 게임 종료 중에는 멈춘다.

적용 후에는 세 직업의 이동 중 공격, 근접·원거리·회복 병종, 좌우 반전 장애물의 앞뒤 가림, 경험치 4색 전환, 보스 경고와 방벽을 게임에서 확인한다. 공격·충돌·시간 연결 코드를 수정했다면 기존 관련 회귀 검사와 `npm test`, `npm run build`를 실행하고 화면 확인 결과와 구분해 기록한다. 문서만 수정한 단계의 형식 검사를 실제 이미지·게임 실행 검증으로 보고하지 않는다.

## 13. 제공 원본 가공 및 적용 현황

| `priest` | 56×64 | (28,60) | 48 | 가장 큰 몸체만 |
| `commander` | 144×132 | (72,128) | 100 | 가장 큰 몸체만 |

적의 셀은 4.3절의 생성 규격보다 넓다. 활시위·창·철퇴를 뻗은 공격 프레임이 셀에 걸려 그 행만 작게 축소되지 않도록, 축소 없이 가공했을 때의 최대 범위에 맞췄다. 셀은 표시 여백일 뿐 판정 크기는 [적 지침](Enemy/AGENTS.md)의 값을 쓴다. 이웃 프레임의 무기 끝이 섞이지 않도록 대부분 가장 큰 몸체만 남긴다. 마법사는 시전 빛이 몸체와 떨어져 있어 큰 조각을 유지한다. 제공된 기사 원본은 4.2절과 달리 말을 탄 모습이며 그대로 적용했다.

- 불투명 핵 실루엣으로 행·열 경계를 구한다. 명목상의 동일 격자로 잘라 이웃 프레임을 섞지 않는다. 자동 탐지가 실패하는 원본만 애니메이션 설정의 `rects`에 원본 행 우선 `[x,y,w,h,...]`를 지정한다.
- 몸체는 이진 알파이고 완전 투명 픽셀의 RGB도 지운다. 마법·검격은 몸체 이름에 `_magic`을 붙인 별도 시트이며 같은 셀·기준점을 사용한다. 좀비에는 이 파일을 만들지 않는다. 데스 나이트의 idle/walk 보조 시트는 비어 있어도 정상이고 attack의 검격은 필수다(`effect_required`).
- 한 애니메이션의 같은 방향에는 고정 배율과 최근접 샘플링을 사용한다. 최하단 몸체 픽셀을 발 기준선 바로 위에 맞춘다. 넓은 검격과 팔 동작 때문에 몸체가 과하게 축소되지 않도록 데스 나이트·좀비와 적의 캔버스 여유를 늘렸다. 최종 셀·앵커·시트 크기는 프로필을 따른다.
- 가장 큰 몸체만 남길 때는 그 조각에 속한 픽셀에서 몸체를 채운다. 경계 상자 안의 다른 조각에서 시작해 몸체가 비는 오류를 고쳤으며, 기존 PNG 바이트는 바뀌지 않았다.
- 동작은 대기·걷기와 행동 하나가 기본이고, 공격과 시전을 모두 가진 성기사단장만 4개다. 표시 기록에 `sheet: 'cast'`가 있으면 시전, 없으면 프로필의 첫 행동 동작을 재생한다.
- `{id}.json`의 `sheets`에는 원본 SHA-256, 추출 사각형·접지점·방향별 배율, 최종 규격을 기록한다. `input_hash`와 `outputs`는 변경 감지에 사용한다. 보조 시트는 기본 P0 파일 수에 별도로 더한다.
- 공격은 실제 전투 기록 직후 정점 프레임에서 재생하며 판정을 지연하지 않는다. 기록·재생 규칙은 [전투 지침](Combat/AGENTS.md#일시정지와-재개)과 [UI 지침](ui/AGENTS.md#직업-표시)을 따른다.

#### 투사체·구슬·효과 가로 시트

제공 원본은 작은 그림을 크게 키운 투명 PNG다. 프로필에 `"layout": "strip"`을 두면 가공기가 다음 순서로 처리한다.

1. 기본은 가장 넓은 빈 열 간격으로 프레임을 나눈다. 빛이 이웃 프레임과 이어져 빈 열이 없는 효과는 `split: valley`로, 균등 분할 위치 ±30% 안에서 알파 합이 가장 작은 열을 경계로 삼는다.
2. 가장 넓은 프레임이 `target_width`px가 되는 하나의 배율로 모든 프레임을 줄이며, 출력 픽셀마다 원본 영역의 가운데 절반만 평균한다. 축소 비율이 작아 그 범위에 원본 픽셀이 없으면 가장 가까운 한 픽셀을 쓴다(투명 줄 방지).
3. 기준점(`pivot`)에 맞춰 셀에 배치한다. `align: core`는 가장 밝은 불투명 픽셀의 가로 중심(발광탄의 핵), `center`는 그림 경계의 중심, `bottom`은 그림 바닥을 셀 바닥에 두고 가로 중심을 기준점에 맞춘다(빛기둥·흙더미). 원본의 픽셀 격자 간격 자동 추정은 축마다 결과가 달라 쓰지 않는다.
4. `alpha: binary`는 화살·볼트·구슬처럼 0/255로, `soft`는 발광탄·구체처럼 반투명 가장자리를 남긴다.
5. `palettes`가 있으면 첫 색은 원본 그대로 두고, 나머지는 기준색과의 색상(hue) 차이만큼 돌린 변형을 `{id}_{suffix}.png`로 만든다.

### 13.2 토큰을 적게 쓰는 재가공

Windows PowerShell의 기본 `System.Drawing`을 사용한다. Python·이미지 패키지·이미지 생성 AI 호출은 필요 없다.

```powershell
# 모든 설정 검사: 원본·설정·가공기 해시와 산출물 해시가 같으면 cached
npm.cmd run sprites:process

# 변경한 종류만 가공
npm.cmd run sprites:process -- -Asset death_knight

# 같은 입력을 강제로 다시 만들 때만 사용
npm.cmd run sprites:process -- -Asset death_knight -Force
```

기존 `scripts/process-warlock-sprites.ps1` 명령은 공통 가공기의 워록 진입점으로 유지한다.

1. 우선 `sprite/reports/processing-report.json`만 읽는다. `processed / cached / missing / failed`와 오류를 보고하며, 누락·실패가 있으면 종료 코드 1이다.
2. `cached`는 이미지 디코딩·미리보기 생성·산출물 재쓰기를 생략한다. 전체 원본을 AI에게 다시 보여주지 않는다.
3. `processed`는 `{id}-preview.png`에 네 방향의 동작별 첫 프레임·중간 프레임만 모은다. 새 종류나 외형 변경 때 이 작은 파일을 먼저 본다. 오류에 프레임 위치가 있으면 그 부분만 추가 확인한다.
4. 임시 폴더에서 모든 시트를 검사한 뒤 파일을 교체하고 메타데이터를 마지막에 갱신한다. 가공·검사 실패는 기존 정상 게임 파일을 덮지 않으며, 게시 중 예외가 발생하면 이전 바이트를 복구한다. 자산 종류끼리는 독립 처리한다.
5. 재현성·캐시·누락·변조 복구·실패 보존은 `tests/sprite-pipeline.test.mjs`, 모든 최종 PNG와 재생은 `tests/sprite-application.test.mjs`로 검사한다. 기존 워록 검증도 유지한다.

다음 요청에는 다음처럼 범위를 좁히면 된다.

> 스프라이트 가이드 13절과 처리 보고서, 변경한 종류의 프로필만 확인하라. 공통 가공기를 실행하고 cached는 이미지로 열지 마라. 새 종류의 작은 미리보기와 실패한 프레임만 검토하라. 게임 연결 코드가 바뀐 경우 관련 지침·코드·테스트를 추가 확인하라.

작은 미리보기와 자동 검사는 원본 모든 프레임의 의상·무늬·해부학적 일관성을 보증하지 않는다. 원본 AI 그림의 세부 차이는 남을 수 있다.
